> 근거는 Forgejo(`fg.dclub.kr`, 계정 kim) 저장소를 API로 읽은 내용입니다. 실행해서 확인한 것은 아니며, PASS·BLOCKED는 저장소 증거 파일에 적힌 그대로입니다.

오늘 통화에서는 "프리랭이 C 언어가 차지하고 있는 백엔드 영역을 대체할 수 있는가"를 논의했습니다.

그 결과 대체를 막는 약점들을 찾았고, 이를 한 고리씩 풀어 나갈 순서를 "킬 체인"으로 정했습니다.

## 3. Script 층 분석 결과 (`freelang-script`)

### 3-1. 명령어
- 진입점은 `bin/fl-script-unified.js`, 버전은 1.2.0입니다.
- 명령: `run`, `check`, `repl`, `web`, `strings`, `pkg`, `test`, `async`.
- `run`·`check` 옵션: `--allow-read/write/net/env`, `--diag-format=json`, `--auto-fix`(check 전용, 미리보기만), `--max-instructions`, `--max-time`, `--max-memory`.
- 막혀 있는 것(모두 `SemanticRouterRequired` 오류): `pkg init`, `test`(모든 시험을 BLOCKED 처리), `async write-file/fetch`, `v1`, `universal`, `--audit-log`.

### 3-2. 권한 구조
- 기본값은 전부 거부입니다.
- 실제로 열리는 권한은 **읽기와 환경변수 두 가지뿐**입니다.
- 쓰기·네트워크·프로세스 실행·DB는 권한 검사보다 먼저 설치되는 차단 경계에서 막힙니다. `--allow-write`나 `--allow-net`을 줘도 Script에서는 열리지 않습니다(코드로 판단).
- 빈틈으로 보이는 곳(코드 관찰, 실행 확인 안 함)
  - `import`가 파일을 읽을 때 읽기 권한 검사를 거치지 않습니다.
  - 경로 범위 검사가 심볼릭 링크를 풀지 않습니다.
  - ai-multi 가지의 `fl-abi-*`, `fl-sys-write`는 권한 검사 없이 네이티브 보조 프로그램을 실행합니다.

### 3-3. 패키지 관리
- 설정 파일은 `freelang.json`, 잠금 파일은 `freelang.lock.json`입니다.
- 잠금 파일에 무결성 해시가 없습니다.
- 원격 저장소 조회나 내려받기 코드가 없고, **로컬 상대경로 import만** 확인합니다.

### 3-4. 오류 안내
- 텍스트 형식: `AI-DIAG 파일:L줄 [오류종류] 메시지` + `GUIDE:` 안내.
- JSON 형식도 있고, 함수 이름 오타는 교정 후보를 제시합니다.
- 약점: 줄 번호를 못 찾으면 1번 줄로 표시, 안내 문구가 두 종류뿐, 한국어와 영어가 섞여 있음.

### 3-5. V11 참조 방식
- 복사가 아니라 참조입니다. `/home/kim/kim/platform/freelang-afj` 작업 폴더의 lexer·parser·interpreter를 esbuild로 메모리 안에서 묶어 실행합니다.
- 버전이나 커밋 고정이 없어서, 그 폴더가 바뀌면 Script 동작도 바뀝니다.
- V11 폴더를 못 찾으면 도움말을 포함한 모든 명령이 시작 단계에서 죽을 것으로 보입니다(코드 판단).

### 3-6. 검증 상태
- "System Profile 9/9 PASS"는 C 파일을 빌드해 확인한 시험 9개입니다(freestanding, ABI, 메모리, 시스템 호출, 부팅, 인터럽트, 스케줄러, 장치, AI OS). **Script 코드 자체를 시험한 것이 아닙니다.**
- 남은 BLOCKED: P1 10건, P2 3건, v2-7 벤치마크, FX 호환 3건.

### 3-7. 백엔드 대체 발판 판단
- 현재는 파일 쓰기, 외부 HTTP, 프로세스 실행, DB가 막혀 있어서 운영 도구(PM2 보조, 배포 스크립트 등)를 대체할 수 없습니다.
- 지금 가능한 범위는 읽기 전용 점검, 환경변수 검사, 인증이 붙은 작은 웹 API(`fl-script web serve`, 사용자별 JSON 저장소) 정도입니다.
- 장점으로 쓸 만한 발판: 기본 거부 권한 모델, 구조화된 진단, 실행 단계·시간·메모리 제한.

## 4. V11 분석 결과 (`freelang-v11`, 기준 커밋 `31075c09`)

### 4-1. 패러다임
- 괄호식 리스프 계열이고, 타입스크립트 해석기가 코드 구조(AST)를 바로 따라가며 실행합니다.
- 함수를 값으로 다루고, 클로저, 매크로(`defmacro`), 패턴 매칭(`match`), 구조체(`defstruct`), 꼬리 재귀 반복 처리가 있습니다.
- 타입은 실행할 때 정해지고, 정적 타입 검사기는 별도 도구입니다.

### 4-2. 메모리 모델
- 해석기 실행: Node(V8)가 자동으로 회수합니다.
- C 런타임: 참조 횟수 칸만 있고 줄이거나 해제하는 코드가 없습니다. 할당만 하고 프로세스가 끝날 때 운영체제가 회수합니다(`core.c:354` "Arena는 Phase B에서 추가").

### 4-3. 동시성 한계
- Node 한 스레드 위의 타이머와 자체 Promise가 전부입니다.
- `await`는 끝나지 않은 작업을 기다리지 못하고 오류를 냅니다.
- `parallel`은 실제로는 차례로 실행합니다.
- 타이머는 함수 이름 문자열로만 등록합니다.

### 4-4. 표준 라이브러리 규모
- FL 모듈 73개, 타입스크립트 모듈 79개, 함수 서명 491개, 별칭 225개.
- 파일·프로세스·DB(node:sqlite, MariaDB, PostgreSQL, MongoDB)·HTTP 기능은 모두 Node 모듈을 감싼 것입니다.

### 4-5. 백엔드 약점 세 가지
1. **조용한 실패**: 파일 읽기·쓰기가 실패해도 `null`/`false`만 돌려줍니다. `parallel` 안의 오류도 `null`로 삼켜집니다.
2. **전역 상태 함정**: 전역 값을 `define`이나 `set!`으로 바꿔도 반영되지 않는 경우가 있습니다(`docs/LANGUAGE-FAULTS.md` #17, #18). 지금은 atom을 쓰는 우회만 있습니다.
3. **HTTP 프로세스 재생성**: HTTP를 한 번 부를 때마다 Node 프로세스를 새로 띄우고 끝날 때까지(최대 15초) 기다립니다. 그동안 전체 실행이 멈춥니다. 일부 HTTP 경로는 상주 작업 스레드 방식으로 개선되어 있습니다.

### 4-6. 참고
- 자가 호스팅 고정점 기록이 서로 어긋납니다. 로드맵·블로그는 달성으로 적었지만, 05-17 깊이 10 검증 결과는 10번 중 9번 실패입니다.
