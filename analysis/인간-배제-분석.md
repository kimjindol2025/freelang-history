# FreeLang 이름 언어들: "인간을 얼마나 배제했나" 분석

> 이 문서의 언어들은 **한국어·영어·일본어처럼 각각 따로인 언어**입니다. 숫자는 이름의 일부일 뿐이고, 점수가 높다고 더 좋은 언어이거나 낮다고 덜 된 언어라는 뜻이 아닙니다. 점수는 한 축 위의 **위치**일 뿐입니다.

## 1. 이 축이 뜻하는 것

- 한쪽 끝은 **인간용 언어**, 다른 쪽 끝은 **AI용 언어**입니다.
- 점수는 "**그 언어가 인간을 얼마나 배제했나**"입니다. 0%는 완전히 인간을 위해 만든 언어이고, 숫자가 클수록 인간을 위한 배려(읽기 쉬운 겉모양, 편의 문법, 사람에게 말하듯 쓴 문서 등)를 덜어 내고 AI가 쓰고 읽기 좋은 쪽으로 간 언어입니다.
- 만든 사람이 매긴 점수는 넷입니다: **FreeLang v1 0%, FreeLang v2 10%, FreeLang v9 70%, AFJ Language(= FreeLang v11) 80%**. 이 문서에서 이 넷은 **공식 점수**이고, 나머지는 조사자가 증거를 보고 붙인 **추정**입니다. 추정은 반드시 "추정"이라고 적었습니다.
- AFJ Language를 지금 쓰는 이유는 AI에 가장 가깝기 때문입니다. 다른 언어들은 실패한 것이 아니라 일부러 멈춰 둔 상태입니다.
- 주의할 점: "AI를 위한 기능이 있다"와 "인간을 배제했다"는 **같은 말이 아닙니다**. 예를 들어 AI가 쓰기 쉽도록 문법을 아주 너그럽게 만들면, 그건 사람에게도 너그러운 언어가 됩니다(배제 0%). 반대로 "사람이 읽기 편한 모양을 위해 구조를 양보하지 않는다"고 정하면 그때 비로소 배제가 생깁니다.

## 2. 판단 기준 9가지

각 기준마다 ○=사람 쪽, ●=AI 쪽, ◐=섞여 있음, –=확인 안 됨 으로 표시했습니다.

| 번호 | 기준 | 사람 쪽(○) | AI 쪽(●) |
|---|---|---|---|
| 1 | 겉모양 | 영어·한국어 문장에 가까운 낱말, 익숙한 C·파이썬 모양 | 모든 것을 괄호로 묶는 규칙적인 모양(괄호 목록형) |
| 2 | 구조 표시 | 들여쓰기처럼 눈으로 보는 표시 | 괄호·중괄호처럼 기계가 세기 쉬운 명시적 표시 |
| 3 | 규칙의 수 | 생략 가능한 부분, 같은 뜻을 여러 방식으로 쓰는 편의 문법이 많음 | 적은 수의 균일한 규칙 |
| 4 | 오류 메시지 | 사람에게 읽히는 문장 위주 | 오류 코드·문맥·수정 힌트를 항목으로 나눠 담음(기계가 읽고 고치기 쉬움) |
| 5 | 암묵성 | 추론·추측·생략을 허용(모호해도 돌아감) | 명시적이고, 같은 입력이면 늘 같은 결과(결정론) |
| 6 | AI 호출 내장 | 없음 | 언어 기본 기능으로 AI 호출·프롬프트·에이전트 |
| 7 | 문서의 독자 | 사람용 안내서·튜토리얼 | AI 에이전트용 문서(CLAUDE.md 같은 AI 작업 규칙, 기계가 읽는 명세 파일) |
| 8 | 검사 가능한 선언 | 없음 | 의도·계약·부작용 같은 것을 코드에 선언하고 도구가 검사 |
| 9 | 도구 | 편집기 확장, 대화형 실행기, 코드 모양 정리기 등 사람 작업용 | 기계가 읽는 출력, 자동 검증 흐름 |

## 5. 언어별 근거

### AFJ Language (= FreeLang v11) — 80% (만든 사람 평가)

**증거가 점수와 맞는가: 맞습니다.** 오히려 문서에 적힌 "원칙"만 보면 80%보다 더 AI 쪽이고, 실제 사용에서 남아 있는 사람 쪽 배려가 80%에 머물게 합니다.

- 기계가 읽는 명세 파일 `SPEC.airc`(JSON 형식)에 이렇게 적혀 있습니다(원문):
  - `"for": "AI 에이전트 (Claude). 인간은 감독자"`
  - `"what": "AI 에이전트가 안정적으로 실행할 수 있는 결정론적 DSL"`
  - 헌법 1조: `"AI 전용. 인간 가독성을 위한 구조 타협 금지"`
  
  (DSL=특정 용도 전용 언어, 결정론적=같은 입력이면 늘 같은 결과)
- AI용 문서: `CLAUDE.md`("Claude AI 완전 레퍼런스"), `docs/CLAUDE_AI.md`("단일 파일에서 Claude가 FreeLang을 완전히 이해 & 즉시 코드 생성", "크기: 5K 토큰 (Context 최적화)"). 사람용 입문서가 아니라 AI가 한 번에 읽도록 분량까지 맞춘 문서입니다.
- 또 다른 기계용 요약 파일 `FREEDOC.fds`: `IDENTITY { domain: ai_native_language  purpose: ai_agents_programming }`.
- 오류 정보가 항목으로 나뉘어 있습니다(`src/error-formatter.ts`): `code`(예: `"E_TYPE_NIL"`), `context`, `hint`, `stack`. 또 자바스크립트·파이썬 습관으로 잘못 쓴 이름을 올바른 이름으로 안내하는 표가 있습니다(예: `"JSON.parse"` → `json-parse`, `"toJSON"` → `json-stringify`). AI가 다른 언어 습관으로 틀리는 경우를 겨냥한 장치로 보입니다.
- 검사 가능한 선언: 함수에 `^{:effects [...]}`(부작용 선언)를 달고 도구가 검사합니다. 설계 문서 `DESIGN-EFFECT-ENFORCEMENT.md`의 문제 정의(원문): "AI 에이전트가 생성한 코드의 의도(`pure`)와 실제 실행(`io`)이 어긋나도 차단되지 않는다." 실행 중 계약 위반을 감시하는 `runtime-contracts.ts`도 있습니다.
- 에이전트 기본 함수: `agent-spawn`, `agent-send`, `agent-recv`, `agent-broadcast` 등.
- 겉모양은 괄호 목록형입니다:

```lisp
(defn make-adder [n]
  (fn [x] (+ n x)))
(define add5 (make-adder 5))
(println (add5 3))
```

- **남아 있는 사람 쪽 배려**: 작업 규칙 "대화는 한국어", 수정 힌트가 한국어 문장, 사람이 읽는 블로그 글이 많음. 또 `docs/LANGUAGE-FAULTS.md`는 인자 순서가 뒤섞인 것 등 "언어 디자인 결함 44개"를 적고, 블로그는 "'실수 100선'이라는 이름이 거짓말이었다 — 80%는 언어 디자인 결함"이라고 씁니다. 규칙을 균일하게 만드는 일이 아직 끝나지 않았다는 뜻이라 3번 기준을 ◐로 두었습니다.

### FreeLang v1 — 0% (만든 사람 평가)

**증거가 점수와 맞는가: 대체로 맞습니다. 단, 한 가지 짚을 점이 있습니다.** 명세서의 목표 문장은 "**AI가 쉽게 쓸 수 있는 언어**"이고 "AI 친화도"를 세 가지 자유도 중 하나로 꼽습니다. 그래서 "AI를 향한 언어"로 읽힐 수도 있습니다. 하지만 이 축은 "인간을 배제했나"이고, v1에는 **사람을 밀어내는 장치가 하나도 없습니다**. 오히려 모든 것을 생략 가능하게 만든, 가장 너그러운 언어입니다. 그래서 0%는 증거와 맞습니다. (코드가 없어 명세서만으로 판단했습니다.)

- 명세서 원문: "설계 철학: '너가 쓸때 편하게 코딩자유를 주는언어'", "세미콜론 선택적 / 중괄호 선택적 (들여쓰기로 대체) / 타입 표기 선택적 (Intent에서 추론) / 괄호 선택적", "부분 구현 가능 (불완전한 코드도 컴파일)".
- 같은 함수를 여러 모양으로 쓸 수 있습니다(명세서 원문):

```
fn sum input array<number> output number intent "합계"
fn sum(arr: array<number>) -> number { sum += arr[i] }
fn sum arr output number { for i in arr { sum += i } }
```

- 의도(intent) 문장은 한국어 자연어입니다. 타입도 의도 문장에서 추측합니다(`intent: "합계"` → 결과는 number). 추측·생략 허용은 5번 기준에서 사람 쪽입니다.
- AI 쪽 흔적은 8번 하나입니다: `intent:`, `directive: speed` 같은 선언, 그리고 "부분 구현 (AI 코드 생성 용) … body는 AI가 채움" 예제.

### FreeLang v10 — 50% (추정)

- 근거: 괄호 목록형(스킴 계열)이라 겉모양·구조는 AI 쪽(●)입니다.

```lisp
(define (get-employee id)
  (let ((result (db_query DB_PATH "SELECT * FROM employees WHERE id = ?" (list id))))
    (if (and result (> (length result) 0))
      (car result)
      null)))
```

- 하지만 저장소 파일 목록에서 AI 호출 기본 함수, AI용 문서(CLAUDE.md 등), 의도·계약 선언을 찾지 못했습니다. 화면 페이지·인증·DB 같은 **사람의 업무 앱**을 만드는 데 쓰인 모양입니다. 그래서 겉모양만 AI 쪽이고 나머지는 사람 쪽이거나 확인 안 됨이라, 50% 안팎으로 추정했습니다.
- 실행기는 FreeLang v9의 해석기를 불러 씁니다(실행 파일 머리말에 적힌 사실). 오류 형식은 이번에 확인하지 않았습니다.

### FreeLang v12 — 75% (추정)

- 근거: 괄호 목록형 + `[FUNC]` 블록. `ARCHITECTURE.md` 원문 "FreeLang v12는 **모듈화 기반의 AI 에이전트 실행 엔진**입니다."

```
[FUNC log-level-num :params [$level]
  :body (get LOG-LEVELS $level)]
```

- `v12-alpha`의 오류 정리 파일에 `code`(예: `"E_TYPE_NIL"`), `context`, `hint`, `stack` 항목이 있습니다(4번 ●).
- `v12-alpha`는 `FL_V12=1`을 켜면 같은 이름 재정의를 오류로 막고, 바뀌는 값은 `atom`으로만 다루게 합니다. 암묵적 동작을 줄이는 쪽이라 5번을 ●로 두었습니다.
- AI용 작업 문서(CLAUDE.md 등)는 두 저장소 파일 목록에서 찾지 못했습니다. 7번이 ◐인 이유입니다. 그래서 AFJ(80%)보다 조금 낮은 75%로 추정했습니다.

### FreeLang v2 — 10% (만든 사람 평가)

**증거가 점수와 맞는가: 맞습니다.** FreeLang v2는 이 목록에서 가장 큰 작업 기록(중복을 뺀 커밋 약 1,180개, 같은 뿌리의 `freelang-evolution`까지 치면 약 1,420개)과 가장 넓은 도구 모음을 가진 언어이고, 그 도구들은 대부분 **사람이 편하게 일하도록** 만든 것입니다. AI를 위한 부분도 분명히 있지만, 그것들은 사람을 밀어내지 않고 **덧붙는** 방식입니다. 10%라는 평가는 이 균형을 잘 보여 줍니다.

**(1) 겉모양: 사람에게 익숙한 문법**

README "언어 문법"(원문 일부):

```
let x = 10
fn add(a, b) {
  return a + b
}
if x > 5 {
  println("크다")
} else {
  println("작다")
}
let tok = { ttype: "INT", lexeme: "42" }
println(tok.ttype)
```

C·자바스크립트를 아는 사람이면 바로 읽을 수 있는 모양입니다. `if` 조건에 괄호를 쓰지 않아도 되는 등 편의도 있습니다.

**(2) 언어 자체를 언어로 만든 작업(자기 호스팅)**

README 제목 "FreeLang v2 — Self-Hosting Compiler". FreeLang으로 쓴 컴파일러 `bootstrap_v2.fl`이 FreeLang 라이브러리를 컴파일해 실행하고(fact(10)=3628800 등), FreeLang으로 쓴 작은 컴파일러를 다시 컴파일하는 3단계까지 README에 결과와 함께 적혀 있습니다. 판 기록(원문 요약): "v2.7 Native-Linter, Native-Graph, Self-Monitoring / v2.8 Native-Expect, Zero-Dependency 달성 / v2.9 Self-Hosting 완성 / v3.0 Level-3 Self-Hosting". (여기서 v2.7, v3.0 같은 숫자는 FreeLang v2 안의 판 번호입니다.)

**(3) 사람 작업용 도구가 매우 많음 (9번 ○)**

본 저장소 `freelang-v2` 파일 목록(2,212개)에서 확인한 것:
- 편집기 확장 두 종류: `vscode-extension/`, `webstorm-plugin/`
- 언어 서버(편집기에 실시간 오류·자동 완성을 주는 프로그램): `src/lsp/lsp-server.ts`, `src/lsp/diagnostics-engine.ts`
- 코드 모양 정리기: `src/cli/format-cli.ts`, `src/formatter/self-format.ts`
- 대화형 실행기: `src/phase-6/smart-repl.ts`("Partial code support (auto-stub generation)", "Smart error handling")
- 자체 검사기(ESLint 대체): `src/linter/lint-gate.ts`
- 표준 라이브러리 README 목록: 문자열·수학·배열·파일·네트워크·DB·암호화·시간

**(4) 사람을 향한 문서 (7번 ○)**

README는 설치 → Hello World → 문법 → 구조 순서의 사람용 안내서입니다. 언어 철학 문서 `PHILOSOPHY_LANGUAGE_AS_ABSTRACTION.md`는 비트겐슈타인 인용으로 시작해 "언어는 무질서한 전기 신호와 트랜지스터의 집합인 하드웨어를 **인간이 이해할 수 있는 자원**으로 바꿉니다"라고 설명합니다. 그 밖에 `LANGUAGE_MATURITY_LEVELS.md`, `LANGUAGE_MAX_SPECIFICATION.md` 같은 언어 설계 문서가 저장소 첫 단에 있습니다.

**(5) AI를 위한 부분 — 사람을 밀어내지 않는 방식**
- 의도 매칭 엔진 `src/engine/intent-matcher.ts`, `intent-patterns.ts`: "AI의 자연어 입력을 자동 헤더로 변환하는 기반". 패턴 낱말이 한국어와 영어입니다(예: `['합산', '더하기', 'sum', 'addition', '합', '누적']`). 자연어로 말해도 알아듣게 하는 장치라 사람에게도 편합니다.
- 타입 추측 `src/analyzer/ai-first-type-inference-engine.ts`: 함수 이름·변수 이름·주석을 보고 타입을 추측합니다(원문 "100% 확신은 없다. 다만 70% 이상의 확률로 맞는 타입을 제안한다"). 사람이 붙인 이름과 주석을 존중하는 방식이고, 추측을 허용하므로 5번은 ◐입니다.
- `@lint(no_unused: error, shadowing_check: warn)` 같은 선언을 함수 위에 달면 컴파일할 때 검사합니다(8번 ◐).
- 오류 분석기 `src/phase-6/error-analyzer.ts`는 오류를 종류·심각도·제안으로 나눕니다(4번 ◐).
- README 목적 문장 "제로 외부 의존성 AI 기반 프로그래밍 언어"와 첫 커밋 메시지 "FreeLang v2 - AI-First Programming Language"에 AI가 들어 있지만, 실제 설계에서 사람을 배제하는 장치(가독성 포기, AI 전용 문서 등)는 찾지 못했습니다.

**(6) 규모** — 자세한 숫자는 [FreeLang v2 문서](../versions/v2.md)의 "규모" 절. 본체 저장소 두 곳(본 저장소) 950개, GitHub 백업 본체 962개, 두 서버 합 1,135개, v2 이름 저장소 전부 합 약 1,180개(모두 중복 제외).

### FreeLang v3 — 15% (추정)

- 근거: 명세서 `V3_LANGUAGE_SPECIFICATION.md` 원문 "V3는 **AI-Friendly, Human-Readable** 프로그래밍 언어입니다. AI-Friendly: 자연어와 유사한 키워드 (ARR, INT, STR 등) / Human-Readable: Python 스타일 들여쓰기, 명확한 문법".

```
IF x > 5:
  println("big")
ELSE:
  println("small")

FUNC add(a: INT, b: INT) -> INT:
  RETURN a + b
```

- 들여쓰기로 구조를 나타냅니다(2번 ○). 대문자 명령어는 명세가 "AI-Friendly"라고 부르지만 겉보기엔 영어 낱말이라 1번은 ◐.
- "AI Intent 모드"(자연어 의도 → 중간 코드 생성·실행), 오류 종류 목록(`NULL_REFERENCE`, `TYPE_MISMATCH` 등)과 자동 수정 기능(`AutoFixEngine`)이 있습니다.
- 사람을 배제하는 장치는 없고 두 목적을 함께 내세우므로 15%로 추정했습니다.

### FreeLang v4 — 20% (추정)

- 근거: 중괄호·정적 타입의 익숙한 모양(1번 ○), 편집기 확장(`vscode-extension/`) 있음(9번 ○).

```
var numbers = [5, 2, 8, 1, 9, 3]
var sorted = sort(numbers)
for x in sorted {
  println(str(x))
}
```

- AI 쪽: README 표어 "AI-First Programming Language", 형식 명세(`LANGUAGE_INDEPENDENT_SPEC.md`, `spec/` 폴더), 런타임 목표 "모든 런타임 (TypeScript, Python, C, Go, Rust)에서 동일한 결과 생성"(5번 ●), 오류 명세 `SPEC_13_ERROR_HANDLING.md`의 "에러 객체: 오류 타입, 메시지, 코드를 구조화".
- 저장소에 LLM으로 테트리스를 두는 도구 같은 AI 실험 파일이 있지만 언어 기능이라기보다 이 언어로 만든 프로그램입니다.
- 사람용 모양을 유지하면서 명세·결정론 쪽이 강해 20%로 추정했습니다.

### FreeLang v5 — 30% (추정)

- 근거: README 원문 "**AI가 주도적으로 코드를 생성하고 최적화**하는 … **Human 10% + AI 90%**". 흐름: 사람의 자연어 의도 → 의도 해석 → 여러 언어 코드 자동 생성.
- 의도 해석기 `src/core/parser/v5-intent-parser.ts`는 첫 줄에서 AI 회사 SDK(`@anthropic-ai/sdk`)를 불러 씁니다. 의도는 `action`(create·modify·analyze…)과 `context`(function·server·data…) 같은 정해진 항목으로 나뉩니다(6·8번).
- 사람을 **코드 쓰는 자리에서 뺐다**는 점에서 배제가 있습니다. 하지만 사람은 가장 편한 방식(자연어)으로 참여하고, 결과물도 사람이 읽는 흔한 언어 코드입니다. 그래서 30%로 추정했습니다. `.v5` 파일 자체는 중괄호형(`fn fib(n: number) -> number { … }`)입니다.

### FreeLang v6 — 5% (추정)

- 근거: 자바스크립트 비슷한 모양, 모듈 불러오기 두 방식, 클로저, enum, 제네릭. C 코드로 바꿔 실행 파일을 만듭니다.

```
import "math" as M
println("3 + 4 = " + M.add(3, 4))
import { mul } from "math"
println("6 * 7 = " + mul(6, 7))
```

- 파일 목록에서 AI 호출·의도·AI용 문서를 찾지 못했습니다. 불러오기를 두 방식으로 허용하는 것은 사람 편의(3번 ◐)입니다. 가장 사람 쪽인 언어 중 하나로 보아 5%로 추정했습니다.

### FreeLang v7 — 추정 불가

- 본 저장소·백업 어디에도 코드가 없습니다. 다른 저장소 문서에 이름만 나옵니다. 판단할 증거가 없어 점수를 붙이지 않았습니다.

### FreeLang v8 — 10% (추정)

- 근거: 중괄호형, 행렬곱 연산자 `@` 같은 수학자에게 익숙한 기호(1번 ○).

```
let a = [[1.0, 2.0], [3.0, 4.0]]
let b = [[5.0, 6.0], [7.0, 8.0]]
let c = a @ b
print(c)
```

- 타입 오류 보고(`src/types/type_error.ts`)가 `kind`(예: `tensor_shape_mismatch`), 줄·칸, `hint`로 나뉘어 있습니다(4번 ◐). 이름으로 타입을 추측하는 파일(`ai-first-type-inference-engine.ts`)도 있습니다.
- "기계학습(AI를 만드는 일)을 위한 언어"이지 "AI가 쓰는 언어"는 아닙니다. 이 축에서는 사람 쪽에 가깝다고 보아 10%로 추정했습니다.

### FreeLang v9 — 70% (만든 사람 평가)

**증거가 점수와 맞는가: 맞습니다.** AI 쪽 장치(괄호 목록형, AI 블록, AI 호출 내장)가 뚜렷하고, AFJ(80%)와 비교하면 사람 쪽 배려가 조금 더 남아 있습니다.

- README(삭제 직전 판) 첫머리 원문: "**AI를 위한, AI에 의한, AI가 쓰고 싶은 언어.**"
- 의도·프롬프트를 블록으로 선언합니다(`examples/simple-intent.fl`, 원문):

```
[INTENT transfer-money
  :from (ref account :id $from-id)
  :to (ref account :id $to-id)
  :amount 1000.50
]

[PROMPT analyze-sentiment
  :input "This product is amazing!"
  :model "claude-haiku"
  :temperature 0.7
]
```

- AI 호출 기본 함수: `(ai-call "claude-3" code-review-prompt)`, `prompt-template`, `rag-search`, `embed`(예제 주석: "모든 함수는 mock으로 동작"). 저장소에 `stdlib-ai.ts`, `stdlib-agent.ts`, `multi-agent.ts` 등 AI·에이전트 파일이 20개 넘게 있습니다.
- **사람 쪽으로 남은 것**: 문자열 안 변수 끼우기(`"나는 {$name}이고…"`), `[FUNC]`·`[ROUTE]`·`[INTENT]`·`[PROMPT]` 등 여러 블록 문법(3번 ○ — 규칙이 늘어남). 오류 정리 파일(113줄)은 위치·소스 강조와 "힌트: …" 한국어 문장 위주이고, AFJ에 있는 오류 코드·문맥 항목은 이 저장소 판에는 없습니다(4번 ◐). AI 전용을 선언한 명세 파일(AFJ의 `SPEC.airc` 같은 것)도 찾지 못했습니다(7번 ◐).
- 이 차이들이 AFJ보다 10%p 낮은 평가와 잘 맞습니다.

## 6. 정리

- 만든 사람이 매긴 네 점수(v1 0%, v2 10%, v9 70%, AFJ 80%)는 모두 증거와 맞았습니다. 짚을 점은 v1 하나입니다. 명세서 목표가 "AI가 쉽게 쓸 수 있는 언어"이지만, 사람을 밀어내는 장치가 없어 "배제" 축에서는 0%가 맞습니다.
- 추정 점수(v3 15%, v4 20%, v5 30%, v6 5%, v8 10%, v10 50%, v12 75%)는 조사자의 판단이며, 만든 사람의 평가가 아닙니다. 특히 v10은 AI 쪽 증거가 겉모양밖에 없어 불확실성이 큽니다.
- 조사 방법: 이 컴퓨터에 남아 있던 문서와, kim27에서 본 저장소 API로 작은 파일 몇 개(README, 명세, 오류 정리 파일 첫 부분, 파일 목록)만 읽었습니다. 저장소를 통째로 복제하지 않았습니다.
