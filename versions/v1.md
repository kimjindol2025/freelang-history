- 규모는 **문서끼리 숫자가 다릅니다**(아래 4번 참고).

## 3. 어떤 언어인가 (명세서 기준)

명세서가 밝힌 목표와 철학을 그대로 옮깁니다.

> **목표**: AI가 쉽게 쓸 수 있는 언어
> **설계 철학**: "너가 쓸때 편하게 코딩자유를 주는언어"
> **버전**: v1.0-alpha (Phase 1, Q1 2026)

- 문법 모양: **들여쓰기 중심, 괄호·세미콜론·타입 표기를 모두 "선택"으로 둔 형태**. 함수마다 `intent:`(의도), `input:`, `output:`, `directive:`(최적화 힌트)를 적습니다.
- 핵심 특징(명세서의 "3가지 자유도"): 문법 자유도(세미콜론·중괄호·괄호 선택), 코딩 자유도("부분 구현 가능 — 불완전한 코드도 컴파일"), AI 친화도.

명세서에 실린 예시(원문 그대로):

```freelang
fn sum
  intent: "배열의 합계"
  input: numbers: array<number>
  output: number
  directive: speed
  do
    result = 0
    for i in 0..numbers.len()
      result = result + numbers[i]
    return result
```

## 4. 상태

- 코드가 없어 실행 여부는 **확인 안 됨**.
- 문서끼리 숫자가 맞지 않습니다.
  - `PLAN_Q2_2026_v2.2.0_WITH_V1_INTEGRATION.md`: "v1 FreeLang — 상태 Phase 14/14 완료, 코드 18,000 LOC, 패키지 31개, 테스트 385개(통과)".
  - `V1_V2_V3_ANALYSIS.md`: "v1 — 소스 파일 304, 소스 LOC 109,515, 커밋 406, 테스트 결과 140 실패".
  - 둘 중 무엇이 맞는지는 **확인 안 됨**.

## 5. 다른 FreeLang 이름 언어와 구별되는 점

- 문법이 **함수마다 의도(intent)를 적는 들여쓰기형 명세 문법**이라는 점이 뚜렷합니다. 중괄호형(v2·v4·v5·v6)이나 괄호 목록형(v9·AFJ)과 모양이 다릅니다.
- 명세서만 있고 코드 저장소가 없는 유일한 경우입니다.
